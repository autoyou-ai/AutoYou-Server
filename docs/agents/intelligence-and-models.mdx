# Intelligence & Model Agents

Intelligence & Model agents govern long-term semantic memory recall, dynamic user personas, hardware-aware model selection, external multi-agent bridges, and advanced reasoning architectures.

---

## 1. `memory_agent`

- **Location**: `autoyou_agents/memory_agent/`
- **Role**: Long-term semantic memory subagent. Maintains a searchable vector and keyword index of user facts, preferences, past conversations, and project context across sessions.
- **Underlying Engine**: Integrated with SQLite-vec and optional Cognee knowledge graph indexing.
- **Key Tools**:
  - `store_memory(fact: str, category: str = "general")`: Stores a permanent memory entry with timestamp and semantic embeddings.
  - `search_memory(query: str, limit: int = 5)`: Retrieves relevant historical facts using cosine similarity or keyword ranking.
  - `forget_memory(memory_id: str)`: Removes a memory entry upon user request to honor privacy and data deletion rights.
  - `list_memories(category: str = None)`: Enumerates stored memories grouped by category.

---

## 2. `persona_agent`

- **Location**: `autoyou_agents/persona_agent/`
- **Role**: Manages user-authored self-data profiles and persona definitions in Markdown format (`persona.md`). Enables tailoring tone, communication style, boundary rules, and domain expertise for all interacting agents.
- **Frontend**: Available via the internal agent proxy at `http://127.0.0.1:8067/agent/persona_agent/`.
- **Key Tools**:
  - `get_active_persona()`: Reads current persona profile Markdown and extracted attribute tags.
  - `update_persona(content: str)`: Updates persona guidelines and voice characteristics atomically.
  - `reset_persona_to_default()`: Restores baseline helpful, neutral assistant persona.

---

## 3. `model_picker_agent`

- **Location**: `autoyou_agents/model_picker_agent/`
- **Role**: Hardware-aware local model selector powered by **LLMFit**. Scans host hardware (RAM, VRAM, CPU architecture, GPU compute capability) and recommends optimal model quantization parameters (Q4_K_M, Q5_K_M, Q8_0) that will run without out-of-memory crashes.
- **Key Tools**:
  - `scan_hardware_capabilities()`: Returns available VRAM, total RAM, GPU device name, and compute tier.
  - `recommend_models()`: Proposes the fastest and most capable Ollama or LiteLLM models tailored to the host system.
  - `benchmark_model_speed(model_name: str)`: Measures token generation latency (tokens/sec) and time-to-first-token.

---

## 4. `openclaw_agent`

- **Location**: `autoyou_agents/openclaw_agent/`
- **Role**: Protocol bridge and tool translation layer connecting AutoYou agents to external OpenClaw multi-agent swarms.
- **Key Features**:
  - Translates AutoYou Google ADK tool schemas to OpenClaw action frames.
  - Supports decentralized agent federation and remote task delegation over encrypted transports.
- **Key Tools**:
  - `dispatch_openclaw_task(task_payload: dict)`: Sends a high-level goal to the OpenClaw coordinator.
  - `query_openclaw_status(task_id: str)`: Polls progress and intermediate execution steps.
  - `cancel_openclaw_task(task_id: str)`: Aborts a remote multi-agent workflow.

---

## 5. `hermes_agent`

- **Location**: `autoyou_agents/hermes_agent/`
- **Role**: Specialized interface for Hermes-series models (e.g. Nous Hermes 3). Optimized for complex multi-step reasoning, structured XML/JSON function calling, and deep agentic workflows.
- **Key Tools**:
  - `invoke_hermes_reasoning(prompt: str, context: dict = None)`: Executes complex reasoning chains with explicit scratchpad/thinking traces.
  - `verify_tool_call_compatibility(schema: dict)`: Validates that tool specifications match Hermes function calling conventions.
