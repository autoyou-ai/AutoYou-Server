# Self-Improvement Loop & Harness Testing

Reliable agent development requires rigorous automated verification that bridges the gap between static unit tests and dynamic, multi-turn LLM conversations.

AutoYou provides two complementary testing systems:
1. **The Self-Improvement Loop (`goal_loop.py`)**: A host-side integration harness that exercises the live ADK agent graph through the exact HTTP/WebSocket surfaces used by production clients, parses server logs for error patterns, and synthesizes repair proposals.
2. **Harness Testing Framework**: Developer tooling for unit testing tool schemas, progress-response interceptors, and multi-turn subagent delegation in isolated test environments.

## 1. The Self-Improvement Engine: `goal_loop.py`

[`autoyou_agents/self_improvement/goal_loop.py`](https://github.com/autoyou-ai/AutoYou-Server/blob/main/autoyou_agents/self_improvement/goal_loop.py) is intentionally written as **ordinary Python**, not as another LLM-driven ADK agent. This guarantees that test execution is deterministic, reproducible, and immune to model failure loops.

### CLI Synopsis & Configuration Flags

```powershell
python autoyou_agents/self_improvement/goal_loop.py \
  --goal "Create a note about project roadmap and search for it" \
  --agent notes_agent \
  --admin-port 8001 \
  --ai-agent-port 8081 \
  --max-iterations 2 \
  --repair-mode codex-prompt
```

| Argument | Default | Description |
| :--- | :--- | :--- |
| `--goal` | *(Required)* | Natural language objective or test description to execute. |
| `--agent` | `None` | Optional target specialist to pin or assert routing for. |
| `--host` | `127.0.0.1` | Hostname or IP address of the target server. |
| `--admin-port` | `8001` | Admin console port for authentication and dashboard status. |
| `--ai-agent-port` | `8081` | AI worker daemon port for direct chat turn dispatch. |
| `--password` | `1234` | Admin login password used to acquire the `AdminSession`. |
| `--session-id` | `uuid4` | Conversation session identifier (auto-generated if omitted). |
| `--max-iterations` | `1` | Number of test and retry iterations to attempt. |
| `--allow-code-edits` | `False` | When `True`, allows the harness to apply automated code patches. |
| `--allow-main-restart`| `False` | When `True`, allows restarting the main server process on failure. |
| `--repair-mode` | `codex-prompt` | Output format: `codex-prompt`, `json`, or `markdown`. |

### Step-by-Step Execution Lifecycle

The execution lifecycle of `goal_loop.py` consists of five distinct phases:

#### Phase 1: Runtime Discovery & Health Probe
The harness checks whether the AutoYou server is already running on the target ports:
- Probes `http://127.0.0.1:8001/` and `http://127.0.0.1:8081/`.
- Resolves process identities (`ProcessIdentity(pid, name, cmdline)`).
- If ports are offline, it attempts a safe ephemeral bootstrap of the server into an isolated test log.

#### Phase 2: Admin Session Acquisition
The harness establishes an authenticated cookie jar (`AdminSession`):
```python
# Submits credentials to acquire an authenticated session cookie
login_payload = {"password": config.password}
response = client.post("/login", json=login_payload)
# Validates session cookies: autoyou_admin_session
```

#### Phase 3: Multi-Turn Conversation Execution
The goal is parsed into one or more `PromptCase` test turns:
```python
@dataclasses.dataclass(frozen=True)
class PromptCase:
    name: str
    message: str
    expected_agent: Optional[str] = None
    expect_totp_gate: bool = False
    must_not_error: bool = True
    description: str = ""
```
Each turn is posted to `/api/ai_agent/chat`, recording the HTTP status, response text, executing agent name, tool call metadata, and latency into a `ChatTurn` record.

#### Phase 4: Error Log Pattern Scanning
During and immediately following turn execution, the harness scans the active server log file against strict error patterns:

```python
_ERROR_LOG_RE = re.compile(
    r"(?:(?:^|\s|\[)(?:ERROR|CRITICAL)\s*[:\]])|"
    r"\b(Traceback \(most recent call last\)|Unhandled|Exception:|"
    r"RuntimeError:|ValueError:|KeyError:|Tool not found|not found in the agent tree)\b",
    re.IGNORECASE,
)
```
Known benign warnings (such as offline optional WhatsApp bridges) are filtered out via `_BENIGN_LOG_RE`.

#### Phase 5: Change Scope Evaluation & Repair Synthesis
If any turn fails or error patterns are detected, `goal_loop.py` determines the required scope of remediation:
- **`agent_runtime_only`**: Failures confined to `autoyou_agents/` can be reloaded without restarting the main server process.
- **`main_runtime_required`**: Changes affecting `core_server/`, `routers/`, or `server.py` require a full server restart.

The run produces a structured `GoalLoopReport` written to:
`output/autoyou_self_improvement/report_<timestamp>.json`

If the run failed, the report synthesizes an actionable **Repair Prompt** containing:
1. Exact failing prompt turn.
2. Model response and observed failure reasons.
3. Relevant server log stack traces.
4. Concrete files to inspect and edit.

## 2. Testing Custom Agent Harnesses

When building custom agents or extending the ADK, you must ensure:
1. Tool argument schemas parse cleanly without truncation.
2. Progress-only conversational responses are intercepted.
3. Multi-turn context is preserved across tool calls.
4. Tests honor `AUTOYOU_TEST_ROOT` and do not mutate operator state.

---

### Step 1: Unit Testing Tool Functions

Every `@tool` function should be tested with standard `pytest` without invoking an LLM.

```python
"""tests/agents/test_my_custom_tool.py"""
import pytest
from autoyou_agents.shared_tools import tool
from autoyou_agents.my_custom_agent.agent import fetch_system_metrics

@pytest.mark.asyncio
async def test_fetch_system_metrics_success():
    result = await fetch_system_metrics(metric_type="cpu")
    
    assert isinstance(result, dict)
    assert result["status"] == "ok"
    assert "cpu_percent" in result["data"]
    assert 0 <= result["data"]["cpu_percent"] <= 100

@pytest.mark.asyncio
async def test_fetch_system_metrics_invalid_type():
    with pytest.raises(ValueError, match="Unsupported metric_type"):
        await fetch_system_metrics(metric_type="unsupported_type")
```

### Step 2: Testing Progress Chatter Interception

Verify that your agent's responses are properly classified by `autoyou_agents.agent_harness`:

```python
"""tests/agents/test_harness_classification.py"""
from autoyou_agents.agent_harness import is_progress_only_response, nonfinal_tool_response

def test_progress_classification():
    # Progress phrases must return True
    assert is_progress_only_response("Let me check that file for you...") is True
    assert is_progress_only_response("I'm going to search the database") is True
    assert is_progress_only_response("Working on it, one moment please") is True
    
    # Completed action phrases must return False
    assert is_progress_only_response("Found 3 records in the database.") is False
    assert is_progress_only_response("Created note 'Project Plan' successfully.") is False
    assert is_progress_only_response("Error: File not found.") is False

def test_nonfinal_tool_response_payload():
    payload = nonfinal_tool_response("autoyou_notes_agent", "Let me search your notes")
    
    assert payload["status"] == "incomplete"
    assert payload["progress_only"] is True
    assert payload["tool_name"] == "autoyou_notes_agent"
    assert "The specialist tool returned only a progress update" in payload["message"]
```

### Step 3: Mocking LLMs in Multi-Turn Tests

To test end-to-end agent orchestration without consuming GPU tokens or requiring an active Ollama instance, mock LiteLLM's `acompletion`:

```python
"""tests/agents/test_agent_orchestration_mock.py"""
import pytest
from unittest.mock import AsyncMock, patch
from autoyou_agents.agent import root_agent

@pytest.mark.asyncio
async def test_root_agent_dispatches_to_specialist(monkeypatch, tmp_path):
    # Ensure test isolation
    monkeypatch.setenv("AUTOYOU_TEST_ROOT", str(tmp_path))
    
    # Synthetic tool call response from the LLM
    mock_llm_response = {
        "choices": [
            {
                "message": {
                    "role": "assistant",
                    "content": None,
                    "tool_calls": [
                        {
                            "id": "call_12345",
                            "type": "function",
                            "function": {
                                "name": "autoyou_notes_agent",
                                "arguments": '{"query": "Meeting notes"}'
                            }
                        }
                    ]
                }
            }
        ]
    }
    
    with patch("litellm.acompletion", new=AsyncMock(return_value=mock_llm_response)):
        # Execute turn through the agent runtime
        response = await root_agent.run_turn(
            prompt="Find my meeting notes",
            session_id="test-mock-session"
        )
        assert response is not None
```

## 3. Safe Testing Contracts & Isolation

When authoring new tests for agents, harnesses, or tools, you **must adhere to these rules**:

<Warning>
  **Never mutate operator state during tests**: Tests must never overwrite `config.keystore.enc`, `agent_install_registry.json`, or the live `sessions.db` database.
</Warning>

1. **Honor `AUTOYOU_TEST_ROOT`**: All persistent stores, caches, and registries must check for `os.environ.get("AUTOYOU_TEST_ROOT")` before falling back to application directories.
2. **Use `tmp_path` Fixtures**: Direct all file writes to pytest's built-in `tmp_path` fixture.
3. **Synthetic Identifiers Only**: Use reserved mock tokens and identifiers (`user_test_123`, `+15555550100`, `test@autoyou.invalid`).
4. **Scope Keyring / Credential Services**: If interacting with OS credential managers, prefix service names with `AutoYouTest_`.

## 4. Running the Regression Gate

Before committing changes to the agent framework, run the project's regression gate:

```powershell
python scripts/e2e_validate.py changed
```

This command automatically:
- Analyzes your `git diff` against tracked subsystems.
- Runs the minimal set of targeted unit and contract tests.
- Verifies that no live configuration files were altered.
- Produces a validation summary report.
