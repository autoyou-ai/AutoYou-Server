# Messaging

The **Messaging** screen (`renderMessagingScreen()` in `assets/admin-ui.js`) keeps the messaging bridges together with only the settings and status each one needs. The bridges are optional. Each routes messages through a third-party service under that service's terms, and you choose which to enable; see [Data Privacy](../security/data-privacy.md). The routes are in the [route catalog](/api-reference/route-catalog).

---

## Panels

| Panel | What it covers |
| :--- | :--- |
| **Server name** | The name AutoYou uses when it responds |
| **Telegram Bot** | A separate bot connection with approved-sender controls |
| **Telegram User** | Your own Telegram account, limited to Saved Messages |
| **Signal** | An optional owner-only connection for Notes to Self |
| **WhatsApp** | An optional owner-only connection for your self chat |
| **AutoYou MCP** | Connects a private MCP adapter to the native chat, models, agents, and supported media handling. See [MCP Integration](../guides/mcp-integration.mdx). |
| **Connected client control** | Select a connected client, send direct messages, and control remote audio playback |
| **Send through Telegram Bot / Saved Messages / Signal / WhatsApp** | Send a message through the paired owner destination |
| **Telegram User activity** | Connection status and recent Saved Messages activity |
| **Signal health & recent messages** | Linked device name, pairing state, service health, and recent messages |

## Telegram Bot

Connects a bot you create with Telegram's BotFather. A message from an unknown Telegram user is held until you approve the sender.

| Route | Purpose |
| :--- | :--- |
| `GET /api/telegram/senders` | Senders that have messaged the bot |
| `POST /api/telegram/senders/approve` | Approve a sender |
| `POST /api/telegram/send` | Send through an approved bot chat |
| `POST /admin/telegram/allow-code`, `POST /api/admin/telegram/allow-code` | Create the code that lets a Telegram user be allowed |

---

## Telegram User

An owner-only transport for **Saved Messages**. It uses Telegram's user API only for the account that completed the local QR sign-in. It never enumerates your chats or reads history: live updates are accepted only when both sides of the conversation are that account's Saved Messages.

| Route | Purpose |
| :--- | :--- |
| `GET /api/telegram-user/status`, `GET /api/telegram-user/qr` | Connection state and the QR code for signing in |
| `POST /api/telegram-user/2fa` | Supply the account's two-step verification password |
| `GET /api/telegram-user/messages`, `POST /api/telegram-user/send` | Recent Saved Messages activity (metadata only; message bodies stay in the consent-gated local path), and sending to Saved Messages |
| `POST /api/telegram-user/restart`, `POST /api/telegram-user/disconnect` | Restart or end the connection |

The console also has an opt-in Telegram Prompt Builder mode that appends Saved Messages to a selected desktop composer.

## Signal

The Signal bridge runs the `bbernhard/signal-cli-rest-api` container, which the server starts through Docker. The repository's Compose file runs the same container beside the server.

| Route | Purpose |
| :--- | :--- |
| `GET /api/signal/status`, `GET /api/signal/detailed-status` | Service and pairing state |
| `GET /api/signal/device-name` | The linked device name |
| `GET /api/signal/qr` | The QR code for linking AutoYou as a device |
| `GET /api/signal/messages`, `POST /api/signal/send` | Recent messages, and sending |
| `POST /api/signal/restart`, `POST /api/signal/cleanup` | Restart the service, or clean up |

---

## WhatsApp

The bridge has two backends, depending on how the server runs:

- **From source:** a Node.js worker (`node/whatsapp/`, `whatsapp_service.py`) built on `whatsapp-web.js` drives a Chromium browser session.
- **In compiled builds:** the `avoylenko/wwebjs-api` Docker container (`whatsapp_docker_service.py`), which avoids the native Node.js modules that do not bundle into a compiled build. The container posts inbound events to `POST /webhook/whatsapp`.

| Route | Purpose |
| :--- | :--- |
| `GET /api/whatsapp/status`, `GET /api/whatsapp/qr` | Connection state and the QR code for signing in |
| `POST /api/whatsapp/send` | Send to your self chat |
| `POST /api/whatsapp/restart`, `POST /api/whatsapp/reset` | Restart the bridge, or reset its session |
