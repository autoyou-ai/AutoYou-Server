# Production Deployment & Hardening

Deployment instructions do not grant additional license rights. Institutional Use and Commercial Exploitation require the separate Enterprise agreement described in [LICENSE](../../LICENSE). Review the selected dependency profile and the actual resolved inventory before deployment.

AutoYou Server is built to run on a computer you control. When you run it on a dedicated machine, an office server, or a virtual machine, use the guidance below. Keep the admin console local: the safest way to reach it from elsewhere is Cloud Pair or Peer Link, not a public address.

---

## 1. Hardening checklist

- [ ] **Choose a security mode.** In the admin console under **Security**, select Secure Professional or Secure Professional Maximus. There is no environment variable for it. See [Security Modes](../security/security-modes.md).
- [ ] **Set up the authenticator** before relying on Secure Professional pairing.
- [ ] **Use a strong, unique server password.** For unattended first setup, provide `AUTOYOU_SERVER_PASSWORD` through your environment or a secret manager rather than a command line.
- [ ] **Keep the default loopback bind.** Every listener binds to `127.0.0.1` unless you set `AUTOYOU_BIND_HOST` (or pass `--host`). Listen on your LAN only when you need to, and expect the server to offer HTTPS when you do.
- [ ] **Rotate the storage key** after a suspected exposure. In Maximus mode, call `POST /api/admin/security/storage/rotate` or use the Security screen.
- [ ] **Approve Telegram senders explicitly.** Discovered senders are approved from the Telegram settings (`POST /api/telegram/senders/approve`).
- [ ] **Decide on public STUN.** The server advertises Google's public STUN servers by default. Set `AUTOYOU_DISABLE_PUBLIC_STUN=1` or `AUTOYOU_LOCAL_STUNTURN_HOST` to change that. See [Data Privacy](../security/data-privacy.md).
- [ ] **Disable what you do not use**: native unlock (`security.native_unlock_enabled`), the MCP bridge (`AUTOYOU_ENABLE_MCP_PARTNER=0`), and the Tunnelmole download (`AUTOYOU_NO_DOWNLOAD_TUNNELMOLE=1`).
- [ ] **Back up** your data folders and test restoring them.

## 2. Docker Compose

The repository ships a `docker-compose.yml` that you can run with:

```bash
docker compose up --build
```

It requires `AUTOYOU_SERVER_PASSWORD`; Compose refuses to start without it. Its main features, from the file in the repository:

- **Ports.** It publishes `8001` (admin), `8067` (page service), `8081` (AI Agent worker), and `8481` (AI Agent worker over HTTPS with a one-time code), each bound to host loopback (`127.0.0.1`). Check how your Docker version publishes ports before relying on loopback isolation.
- **Data.** A named volume, `autoyou-data`, holds the application data.
- **Signal.** A `signal-cli-rest-api` container runs beside the server for the Signal bridge, with its own named volume.
- **Models.** `OLLAMA_API_BASE` points to Ollama on the host.
- **Page service trust.** `AUTOYOU_PAGE_TRUST_NETWORK_PEERS=1` is set because port `8067` is published on the host's loopback only, so the Docker gateway peer is this computer's own browser.

Build arguments let you leave out optional components, for example `AUTOYOU_INCLUDE_COGNEE=0` and `AUTOYOU_INCLUDE_TUNING=0`.

## 3. systemd (Linux)

The supported entry point is the launcher, which prepares the Python environment and then starts the server. This unit is an example; adjust the paths, user, and profile for your system and test it before depending on it.

```ini
[Unit]
Description=AutoYou Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=autoyou
WorkingDirectory=/opt/AutoYou-Server
EnvironmentFile=/etc/autoyou/autoyou.env
ExecStart=/opt/AutoYou-Server/run_autoyou.sh --profile base
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Put `AUTOYOU_SERVER_PASSWORD` in the environment file and restrict its permissions (`chmod 600`, owned by root or the service user). Enable the unit with:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now autoyou
```

## 4. Reverse proxy

Do not publish the admin app (`8001`) on a public address. If you serve agent websites to people outside your network, put a proxy in front of the **page service** (`8067`) only, and terminate TLS at the proxy:

```caddy
apps.example.com {
    reverse_proxy 127.0.0.1:8067
}
```

A proxy delivers requests from `127.0.0.1`. The server treats a request that carries a forwarding header such as `X-Forwarded-For` as coming from somewhere else, so it is handled as a shared device and a remote browser, which cannot change credentials or security settings. Make sure your proxy sets those headers, and keep agent-website sign-in and 2FA on. See [Security & Authentication](/architecture/security-and-auth).
