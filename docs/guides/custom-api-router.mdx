# Adding Custom API Routers

AutoYou Server keeps its HTTP routes in modules under `routers/` instead of in `server.py`. Each module exposes a `register_routes()` function that `server.py` calls once at start-up. This guide adds a small example module, `routers/analytics.py`, following the same pattern. The example name is only an illustration.

The two FastAPI apps and what each serves are described in the [API overview](/api-reference/overview). Put a route on the admin app if it needs a signed-in operator, which is the usual case.

---

## 1. Create the router module

Create `routers/analytics.py`. `register_routes` receives both apps and the server module, and returns a dictionary of names to export into `server.py`'s namespace (empty here):

```python
# routers/analytics.py
"""Example analytics routes."""

from __future__ import annotations

from typing import Any, Callable, Dict

from fastapi import FastAPI, Request


def register_routes(
    admin_app: FastAPI,
    auth_app: FastAPI,
    server: Any,
) -> Dict[str, Callable[..., Any]]:
    @admin_app.get("/api/analytics/summary")
    async def analytics_summary(request: Request):
        """Return a small summary for the signed-in operator."""
        auth_error = server._require_api_login_json(request)
        if auth_error is not None:
            return auth_error
        return {"success": True, "active_sessions": 0}

    return {}
```

`server._require_api_login_json(request)` returns `None` when the request is signed in (a valid `admin_session` cookie, or a valid bearer token) and a `401` JSON response otherwise. Return it as shown. Use `server._require_api_login(request)` for routes whose errors are not JSON. Keep route handlers thin and reuse the server's existing helpers rather than copying logic into the router.

Use the response shape the other routes use: `{"success": true, ...}` on success and `{"success": false, "error": "..."}` on failure.

---

## 2. Register it in `server.py`

Import the module next to the other router imports, then call it after the apps are created:

```python
from routers.analytics import register_routes as register_analytics_routes

admin_app, auth_app = create_apps(LOGGER)
# ... the existing register_* calls ...
globals().update(register_analytics_routes(admin_app, auth_app, sys.modules[__name__]))
```

A route registered on the auth app is part of the public pairing surface and is reachable before the server is unlocked only if it is on the unlock allow-list, so register on `auth_app` only deliberately.

## 3. Test it

Router tests build a bare FastAPI app and a small fake server, so they never touch real configuration or runtime state. Run them with an isolated test root:

```python
# tests/server/test_analytics_router.py
from types import SimpleNamespace

from fastapi import FastAPI
from fastapi.responses import JSONResponse
from fastapi.testclient import TestClient

from routers.analytics import register_routes


def _client(signed_in: bool) -> TestClient:
    def require_login(request):
        if signed_in:
            return None
        return JSONResponse(status_code=401, content={"success": False, "error": "Authentication required"})

    admin_app, auth_app = FastAPI(), FastAPI()
    register_routes(admin_app, auth_app, SimpleNamespace(_require_api_login_json=require_login))
    return TestClient(admin_app)


def test_requires_sign_in():
    assert _client(False).get("/api/analytics/summary").status_code == 401


def test_returns_summary_when_signed_in():
    response = _client(True).get("/api/analytics/summary")
    assert response.status_code == 200
    assert response.json()["success"] is True
```

```bash
AUTOYOU_TEST_ROOT="$(mktemp -d)" python -m pytest tests/server/test_analytics_router.py -q
```

## 4. Update the reference pages

The [route catalog](/api-reference/route-catalog) is generated from the router modules. After adding a route, regenerate it:

```bash
python scripts/generate_reference_docs.py
```

A test fails when the generated pages are out of date. The generator also stops with a message if a module in `routers/` is not listed in `ROUTER_FILES` in `scripts/generate_reference_docs.py`; add your new module there, with a title and a one-line purpose, so its routes appear in the catalog.
