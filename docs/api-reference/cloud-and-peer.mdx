# Cloud & Peer Rendezvous APIs

These routes cover the optional remote-access helpers. The concepts, trust boundaries, and flows are explained in [Cloud Pair & Remote Access](/architecture/cloud-and-remote). The admin-app routes below need an admin sign-in. Errors follow the shape in the [API overview](/api-reference/overview).

---

## AutoYou Cloud (admin app)

| Route | Request | Purpose |
| :--- | :--- | :--- |
| `GET /api/cloud/status` | none | Registration and connection status |
| `GET /api/cloud/link-start` | none | Redirect the browser to the AutoYou Cloud sign-in |
| `GET /api/cloud/callback` | query from the sign-in redirect | Receive the redirect back and save the server token |
| `POST /api/cloud/activate` | none | Make this server the active AutoYou Cloud server for the account |
| `POST /api/cloud/reregister` | none | Register again after the token was rejected |
| `POST /api/cloud/unregister` | none | Remove the registration and stop the event stream |
| `GET /api/cloud/ice-preview` | none | Show the `iceServers` this server would advertise on `/auth` |
| `GET /api/cloud/devices` | none | Devices whose Cloud Pair keys this computer saved, and any awaiting approval |
| `POST /api/cloud/devices/approval` | `required` | Require (or stop requiring) owner approval for new Cloud Pair devices |
| `POST /api/cloud/devices/{device_id}/approve` | none | Accept the key a pending device presented |
| `POST /api/cloud/devices/{device_id}/forget` | none | Drop a saved or pending device key |
| `POST /api/cloud/push-client` | none | Ask paired clients to reconnect through AutoYou Cloud |
| `POST /api/cloud/notify-client` | `title`, `body`, optional `category`, `data` | Send a notification to your opted-in client devices through AutoYou Cloud |

Changing who may pair through AutoYou Cloud (the approval and device routes) is refused for remote browsers.

### Guest access (x402)

| Route | Request | Purpose |
| :--- | :--- | :--- |
| `GET /api/cloud/guest-access`, `POST /api/cloud/guest-access` | `enabled`, `price_credits`, `pass_ttl_seconds` | Read or set the guest-access pricing and mirror it to AutoYou Cloud |
| `GET /api/v1/x402/connect` | none | Discovery: returns the payment requirements (HTTP `402`) |
| `POST /api/v1/x402/connect` | `guest_pass` or `auth_token` | Verify an AutoYou Cloud subscription and issue a short-lived connection token |
| `POST /api/v1/pair` | `text` | Process a pairing command authenticated by an x402 access token |

## Public link (Tunnelmole)

| Route | Purpose |
| :--- | :--- |
| `GET /api/tunnelmole/status` | State of the public link and its URL |
| `GET /api/tunnelmole/website-hosting`, `POST /api/tunnelmole/website-hosting` | Read or set website hosting over the public link |
| `POST /tunnelmole/start`, `POST /tunnelmole/stop`, `POST /tunnelmole/refresh` | Start or stop the public link, or refresh its URL status |

The public link is off by default and, in its default timed mode, closes after a timeout.

---

## Peer Link rendezvous (auth app)

The `/v1/peer/rendezvous/...` routes and `GET /peer/add` are on the auth app and are deliberately unauthenticated. Their routes, behavior, and safeguards are described in [Cloud Pair & Remote Access](/architecture/cloud-and-remote#peer-link-rendezvous). The admin app also serves `GET /api/peer/rendezvous/status`.
