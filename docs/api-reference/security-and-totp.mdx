# Security & TOTP APIs

These admin-app routes manage authentication settings. They need an admin sign-in, and a remote browser cannot use the ones that change credentials or the security posture; see [Security & Authentication](/architecture/security-and-auth). Errors follow the shape in the [API overview](/api-reference/overview).

Routes that save configuration return an error when the configuration cannot be written at that moment.

---

## Security mode and tier

### `POST /api/admin/security/mode`

Request:

```json
{ "mode": "secure_professional" }
```

`mode` is `normal`, `secure`, `secure_professional`, or `secure_professional_maximus`. Any other value returns `400`.

Response:

```json
{
  "success": true,
  "mode": "secure_professional",
  "ai_agent_restarted": false,
  "storage_unsealed": null,
  "storage_recovery": {},
  "bootstrap": {}
}
```

Moving out of Maximus first decrypts the protected stores back to plaintext, so no sealed file is left unreadable, and the response reports that in `storage_unsealed`. The AI Agent worker is restarted when the storage boundary changes. `bootstrap` is the refreshed admin console state.

### `POST /api/admin/security/tier`

Request: `{ "tier": "A" }` for Enhanced Pairing or `{ "tier": "B" }` for Quick Pairing. Other values return `400`. Response: `{"success": true, "tier": "A", "bootstrap": {}}`.

## Password and storage key

### `POST /api/admin/password`

Changes the server password for the signed-in session. The request needs no current password.

```json
{ "new_password": "string", "confirm_password": "string" }
```

The two values must match and the password must pass the strength check, otherwise the route returns `400` with the reason. On success the configuration is re-encrypted under the new password and the response is `{"success": true, "message": "Password updated", "bootstrap": {}}`.

### `POST /api/admin/password/generate`

Generates a strong random password for the console to offer.

### `POST /api/admin/security/storage/rotate`

Rotates the Secure Professional Maximus storage key and re-encrypts the protected data. It returns `409` when Maximus storage is not active. On success it answers `{"success": true, "message": "...", "secure_storage": {}, "ai_agent_restarted": false, "bootstrap": {}}`.

## Shared authenticator (TOTP)

The server keeps one shared authenticator. Codes are the standard six digits that change every 30 seconds, and a code is accepted with one adjacent time step of tolerance. There are two sets of routes with the same effect: the console's `/admin/security/totp/...` routes, and the `/api/native/security/totp/...` routes that the desktop apps use.

| Route | Purpose |
| :--- | :--- |
| `POST /admin/security/totp/generate` | Create and save a new secret immediately and return its setup payload |
| `POST /api/native/security/totp/setup` | Create a secret and QR code **without saving it**. Returns `{"success": true, "secret": "...", "qr_data_url": "..."}`. |
| `POST /api/native/security/totp/confirm` | Save the secret from `setup` only after a code is verified. Body: `{"secret": "...", "code": "123456"}`. A wrong or malformed code returns `400`. |
| `POST /admin/security/totp/show`, `POST /api/native/security/totp/show` | Return the saved secret with its setup URI and QR code. `404` if none is saved. |
| `GET /admin/security/totp/current-code`, `GET /api/native/security/totp/current-code` | Return `{"success": true, "code": "123456", "seconds_remaining": 12, "period": 30}` for the saved secret. |
| `POST /admin/security/totp/import`, `POST /api/native/security/totp/import` | Import an authenticator setup link or a Base32 secret. Body: `{"value": "..."}`. |
| `POST /admin/security/totp/delete`, `POST /api/native/security/totp/delete` | Remove the saved secret. Returns `{"success": true, "target": "pairing"}`. |
| `POST /api/admin/session/verify` | Exchange a valid code for a one-hour bearer token for the admin agent. Body: `{"totp_code": "123456"}`. |
| `GET /api/admin/session/capabilities` | Report whether a usable authenticator is configured. |

The secret and its QR code are returned only to a signed-in admin. Treat them like passwords.

## Per-agent 2FA profiles

Agent websites can each require their own second factor. A profile's secret is derived from the server password and a stored salt, so it is not stored and cannot be shown again.

| Route | Purpose |
| :--- | :--- |
| `GET /api/agent-security/profiles` | List profiles |
| `POST /api/agent-security/profiles` | Create a profile. Body: `{"label": "...", "issuer": "AutoYou"}`. The response's `enrolment` holds the provisioning URI, the manual-entry secret, and a QR code, **once only**. |
| `POST /api/agent-security/profiles/{profile_id}/verify` | Check a code against a profile to confirm enrolment |
| `GET /api/agent-security/profiles/{profile_id}/current-code` | The profile's current code |
| `POST /api/agent-security/profiles/{profile_id}/assign` | Assign the profile to an agent. Body: `{"agent_name": "..."}`. |
| `POST /api/agent-security/profiles/{profile_id}/wipe` | Delete the profile; every agent using it loses its 2FA requirement |
| `GET /api/agent-security/agents/{agent_name}/status` | `{"requires_2fa": true, "profile_id": "..."}` for an agent |
| `POST /api/agent-security/agents/{agent_name}/wipe` | Remove the agent's profile assignment |
| `POST /api/agent-security/verify` | Verify a code for an agent's assigned profile. This is the backend of the agent website's gate. |
| `GET /api/agent-websites/security`, `POST /api/agent-websites/security` | The global agent-website settings: `require_otp`, `disable_otp`, `shared_session_enabled`, and `shared_session_ttl_days` |

If the server is locked, these routes return `409`.
