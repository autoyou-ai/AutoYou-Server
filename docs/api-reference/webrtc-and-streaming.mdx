# WebRTC & Media Streaming APIs

These admin-app routes control the capture devices, calls, playback, and remote input that the WebRTC engine uses. They need an admin sign-in. The transport is described in [WebRTC & DataChannels](/architecture/webrtc-and-datachannels), and the console screens that use these routes are in [Live View, Interact & Media](/admin-ui/live-view-and-media). Errors follow the shape in the [API overview](/api-reference/overview).

---

## Devices and capabilities

| Route | Purpose |
| :--- | :--- |
| `GET /api/webrtc/capabilities` | Capabilities of the WebRTC engine on this computer |
| `GET /api/webrtc/audio-devices` | Audio capture devices |
| `GET /api/webrtc/camera-devices` | Camera devices |
| `GET /api/webrtc/monitors` | Attached displays |
| `GET /api/webrtc/microphone-sharing`, `PUT /api/webrtc/microphone-sharing` | Read or change whether the computer's microphone is shared. `PUT` body: `{"enabled": true}`. |

---

## Calls

| Route | Purpose |
| :--- | :--- |
| `POST /api/chat/call/offer` | Send a call offer |
| `POST /api/chat/call/candidate` | Send an ICE candidate for the call |
| `POST /api/chat/call/close` | End the call |

---

## Sending to a connected client

| Route | Request | Purpose |
| :--- | :--- | :--- |
| `POST /api/webrtc/send` | `message`, optional `context`, `metadata`, `session_id`, `owner_key` | Send a text message to a connected DataChannel client |
| `POST /api/webrtc/client-browser-control` | `payload`, `session_id` or `owner_key`, optional `allow_single_live_fallback` | Send a browser-control message to a connected client |
| `POST /api/webrtc/rewarded-ad` | `payload`, `session_id` or `owner_key`, optional `allow_single_live_fallback` | Send a rewarded-ad control message to a connected client |

---

## Audio playback to a client

| Route | Request | Purpose |
| :--- | :--- | :--- |
| `GET /api/webrtc/playback/enabled`, `POST /api/webrtc/playback/enabled` | `{"enabled": true}` | Read or set whether server-side audio-file playback is allowed |
| `POST /api/webrtc/playback/play` | `file_path`, `session_id` or `owner_key` | Play a local audio file to a client |
| `POST /api/webrtc/playback/pause`, `/resume`, `/stop`, `/status` | `session_id` or `owner_key` | Control or inspect playback |

---

## Video injection

| Route | Request | Purpose |
| :--- | :--- | :--- |
| `GET /api/webrtc/video-files` | none | Uploaded video files |
| `POST /api/webrtc/video-file/upload` | multipart form with a `video` field | Upload a video file |
| `POST /api/webrtc/video-file/play`, `/pause`, `/status` | none | Start, pause, or inspect playback of the uploaded file into the active video track |
| `POST /api/webrtc/video-input/{source_id}/frame` | one of `jpeg_base64`, `image_base64`, `data`, or `data_url` | Feed one frame into a named video input source |

---

## Remote input

| Route | Purpose |
| :--- | :--- |
| `WEBSOCKET /api/webrtc/game-input/stream` | A WebSocket for remote input |
| `GET /api/webrtc/game-input/connection` | The state of the game-input connection |
| `WEBSOCKET /api/webrtc/hosted-game/api/game/native-input` | A WebSocket for native game input |
| `GET /api/webrtc/hosted-game/api/game/native-input/status` | The state of the native input channel |
| `GET /api/webrtc/hosted-game/play` | The hosted game page |

The complete list of WebRTC routes is in the [route catalog](/api-reference/route-catalog).
