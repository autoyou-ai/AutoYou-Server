# Admin & System APIs

These admin-app routes report the server's status, change its configuration, and control its services. Unless noted, they need an admin sign-in. Errors follow the shape in the [API overview](/api-reference/overview), and every route is listed in the [route catalog](/api-reference/route-catalog).

---

## Status

| Route | Purpose |
| :--- | :--- |
| `GET /api/status` | A simple status check: `{"status": "running", "service": "AutoYou Admin Server", "instance": {...}, "runtime": {...}}`. `instance` holds the server name, bind host, and ports (`admin`, `ai_agent`, `auth`, and `page`). |
| `GET /api/v1/status` | The status payload that browser clients read |
| `GET /api/v1/server-config` | The server configuration that browser clients read |
| `GET /api/connection/status` | A connection-helper snapshot, read on the server so no secrets reach the browser |
| `GET /api/datachannel-status` | State of the DataChannel sessions |
| `GET /runtime/owner` | Lets the host that started this process prove that this listener is its own, using a start-time token and request headers. Anyone without the token is told nothing. |

Status payloads describe this computer: its name, its agents, its LAN address, and folder paths. A caller on the network must be signed in to read them. Apps on this computer, and paired devices whose requests the server itself delivers over loopback, read them without signing in again.

## Bootstrap and configuration

| Route | Purpose |
| :--- | :--- |
| `GET /api/admin/bootstrap` | Everything the console needs to render: configuration, status, and metadata |
| `POST /api/admin/config` | Update configuration sections. Sections that widen who can reach the server, such as `security`, `tunnelmole`, and `mcp`, and some `server` keys such as `bind_host`, cannot be changed by a remote browser. |
| `GET /api/admin/permissions`, `POST /api/admin/permissions` | Read or change what this computer allows AutoYou and paired devices to capture, record, and access |
| `GET /admin/api/ui/theme`, `POST /admin/api/ui/theme` | Read or set the console theme |

Password, security mode, and authenticator routes are in [Security & TOTP APIs](/api-reference/security-and-totp). Setup recipes and the wizard are in [Setup & Boot](/admin-ui/setup-and-recipes).

## Scheduler summaries

| Route | Purpose |
| :--- | :--- |
| `GET /api/scheduler/live-summary` | Task counts from Tasks Mission Control |
| `GET /api/scheduler/notification-queue` | Queued reminder and task deliveries waiting for a connection or retry window |

## Service control

All of these are `POST` routes, and each needs an admin sign-in.

| Service | Routes |
| :--- | :--- |
| AI Agent worker | `/ai-agent-server/start`, `/ai-agent-server/stop`, `/ai-agent-server/restart`. Status: `GET /api/ai-agent-server/status`. |
| Page service | `/autoyou-page-service/start`, `/autoyou-page-service/stop`, `/autoyou-page-service/restart`. Status: `GET /api/autoyou-page-service/status`. |
| Public link (Tunnelmole) | `/tunnelmole/start`, `/tunnelmole/stop`, `/tunnelmole/refresh`. Status: `GET /api/tunnelmole/status`. |

### `POST /shutdown`

Starts a graceful shutdown. It accepts either a local shutdown token or an admin session. The server answers `{"success": true, "message": "Server shutdown initiated"}` immediately and begins shutting down about a second later.

### `GET /home-network/websites`

Opens website apps from a browser on another device after signing in. The signed-in admin page hands that browser a one-time code for the websites port, which turns it into a device-pass cookie. See [Website Gateway & Page Service](/api-reference/website-gateway).

## Software updates

`GET /api/software-update/status` and `POST /api/software-update/apply` check for and apply an update. See [Setup & Boot](/admin-ui/setup-and-recipes#software-updates).
