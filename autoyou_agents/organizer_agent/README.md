# Your content in AutoYou

Admin > My Content and the optional Organizer Agent use one private catalog.
Install Organizer from the agent manager to use its website, model tools and
custom-agent imports from the native clients. It requires authenticated access;
its cross-agent API refuses the optional public/open agent mode.

Add files or folders, search by title, label or annotation, and assign a
collection. Filename and type labels are applied locally on first import.
They are not a claim that an AI watched, listened to or understood the file.
The model tools can read saved Pages, Notes, bounded text outputs and native custom records before
annotating them. Source-agent media interpretation remains in that agent.

Use **Index existing content** to add existing Pages, Notes, TV, imported Audio,
generated media and daily location references. This reads known catalogs, not
an unrestricted recursive scan. Existing originals are not moved. New writes
publish catalog references. Removing an indexed note or TV item removes its
catalog entry; manual labels and annotations survive subsequent indexing.

## Storage

The default destination is `content_library/content` under AutoYou's mutable
data root. Storage settings accept an absolute server folder. Restart agents
after changing it. TV, Audio imports, media generation, conversation media,
Organizer uploads and new agent scaffolds use the common output contract.
Catalog databases and older agent databases stay in their own data roots.
Previous output destinations stay discoverable for playback and key rotation.

When Secure Professional Maximus is enabled, new uploads use authenticated
encrypted chunks and an encrypted manifest. HTTP byte ranges decrypt only the
needed chunks. The catalog and native records use Maximus's secure SQLite
adapter. Disabling or rotating keys uses the existing Maximus workflow, which
now includes prior output roots. This feature does not turn Maximus on or
silently encrypt externally linked originals. Existing plaintext files are
not automatically migrated by indexing.

Codecs can require short-lived plaintext input/output while generating a
preview or rendition. Inputs are materialized in temporary files and removed
when the operation finishes; published previews and renditions are sealed.
This is encryption at rest, not protection against a compromised running OS
or a machine crash that leaves a codec temporary file behind. Back up both
the managed file and its adjacent `.parts` directory.

## Device and agent contract

The iOS and Android publish-to-computer flows now accept `custom_*` sources.
Publishing is explicit, requires the existing Editor/Admin role, signs in to
Organizer, uploads attachments in bounded resumable chunks, verifies the saved
bytes and commits the record. Agent kind, record UUID and timestamps remain
stable. A stale or conflicting record receives HTTP 409. Diary/reminder
metadata is preserved as content; importing it does not schedule notifications.
Existing phone-to-phone Peer Link grants remain unchanged. This is an import
and shared catalog, not automatic bidirectional replication of all phone state.

Authenticated API prefixes are `/api/admin/content` on Admin and
`/agent/organizer_agent/api/content` through the agent proxy:

- `GET ?after=<revision>&limit=100`: incremental metadata including removals;
  follow `cursor` until `has_more` is false. For an initial complete sync use
  `after=0`. Normal searches use offset pagination.
- `PATCH /items/<id>`: labels, annotation, collection and `expected_revision`.
- `POST /upload-sessions`: filename, size, source, optional source_id and title.
- `GET/PUT/DELETE /upload-sessions/<id>`: status, chunk with `?offset=`, cancel.
- `POST /upload-sessions/<id>/complete`: publish and return `item`.
- `GET /items/<id>/content`: owner-authorized byte ranges; active formats
  such as HTML and SVG are downloads rather than executable origin content.
- `POST /native`: custom kind, UUID, base_kind, title, body, URL, updated_at in
  milliseconds and completed catalog attachment IDs. Metadata is sealed with
  the catalog. Filenames never become server paths supplied by the client.

Python agents use `shared.content_library.save_output(source, filename,
chunks, title=...)`, with an iterable of bytes. Existing producers can call
`publish_content` after their own transaction commits, or `forget_content`
after removal. Generated agent scaffolds include a text-output tool already.

## Motion and validation

TV, Audio, Media Generation and the shared library consume CSS generated by
the installed OpenMotion source at revision
`1c93d99b064e8674f244a8f24227358ec6f61618`. Regenerate from the parent workspace:

```powershell
node .tmp/autoyou-motion/node_modules/tsx/dist/cli.mjs scripts/website-motion/agents.mts
```

The runtime does not need the OpenMotion studio process. Generated motion
honors reduced-motion preferences and includes the upstream MIT notice.
TV's importer uses a short files/place/play progression, batch imports and
folder preservation. Audio drops go directly to its resumable importer.
TV, Audio and the shared library read dropped folders recursively, including
directory listings returned in multiple batches. Folder discovery finishes
before uploads start and shows a file count. TV preserves the folder hierarchy;
the shared library uses folder paths as collections. Audio adds tracks to its
library. Failed folder discovery leaves server content untouched.
The design references Ampchor's observed onboarding progression and its
[documented folder-first library flow](https://ampchor.com/shows/). Its
[music guide](https://ampchor.com/music/) also keeps originals in place.

All tests must set `AUTOYOU_TEST_ROOT`; no test should read or mutate the
operator's live configuration, content catalog or security settings.
